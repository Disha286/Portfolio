Product thinking

Decisions & why

Transactly
SMS parsing over manual entry
Requiring users to log transactions manually creates too much friction - adoption drops before the product delivers value. Parsing UPI SMS gives instant, effortless data with zero user effort.
Reduce friction
Transactly
Auto-categorization with user override
Fully manual categorization is tedious; fully automatic loses user trust when wrong. Defaulting to smart categorization with easy correction balances accuracy and user control.
User control
LuxeStay
MoSCoW prioritization for scope
A 6-week engagement with limited implementation capacity meant we couldn't build everything. MoSCoW aligned the team on what delivered the most business value vs what was nice to have.
Stakeholder alignment
LuxeStay
Current → future-state journey mapping
Before designing solutions we mapped where users experienced friction in the existing flow. This prevented us from designing features that solved the wrong problem.
Problem first
ProjectFlow
Role-based access control (4 tiers)
Different participants in a project need different levels of access and responsibility. Flattening permissions leads to either information overload or security gaps — RBAC solves both.
Multi-tenant design
ProjectFlow
Burndown charts as default sprint view
Teams need to see velocity and risk in real time, not just task status. Burndown makes progress and blockers visible at a glance — shifting focus from activity to outcomes.
Outcome visibility
